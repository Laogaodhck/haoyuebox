# OCR 文字识别：增强管线、版面还原与导出

> 适用版本：v1.4.1 起 · 2026-10-21
> 相关源码：`js/docs-ocr.js`（子功能主流程）、`js/ocr-enhance.js`（图像增强与版面还原）、
> `js/xlsx-lite.js`（Excel 生成）、`vendor/ocr/`（Tesseract.js v5 与语言包）
> 相关测试：`tools/test-ocr-enhance.cjs`、`tools/test-docs-ocr.cjs`、`tools/test-xlsx-lite.cjs`、
> `tools/verify-ocr.cjs`

本文说明文档工具「OCR 文字识别」的技术实现：如何把模糊、倾斜、低光照、复杂背景的图片尽可能识别准确，
如何把识别结果还原成与原件一致的段落与表格结构，以及三种导出格式各自保留了什么。

## 一、总体流程

```
文件（图片 / PDF）
  → 解码 + 智能缩放（小图放大 / 超大图限长边）
  → 图像增强（纠偏 / 对比度 / 锐化 / 二值化 / 去噪）      ← 可在面板关闭
  → Tesseract LSTM 识别（输出 text + 词级 blocks）
  → 结构化文档模型 {blocks: [段落 | 表格]}                 ← 单一数据源
  → 文本视图（A4 固定版心展示 / 复制）
  → 导出：TXT / DOCX（真表格 + 缩进 + 页面方向）/ XLSX（工作表）
```

关键设计：**识别、展示、导出共用同一份结构化模型**。文本视图、DOCX 与 Excel 都从 `blocks` 渲染，
避免"预览还原了排版、导出却是纯文本"的割裂。

## 二、输入预处理

| 项目 | 规则 | 原因 |
| --- | --- | --- |
| 图片解码 | `createImageBitmap` 解码后绘制到 canvas | 统一送入像素管线，避免重复解码 |
| 小图放大 | 长边 < 1000px 时放大 2–3 倍（双线性高质插值） | Tesseract 对小字号敏感，放大显著提升识别率 |
| 超大图降采样 | 长边 > 2600px 时压到 2600px | 更高分辨率对准确率几乎无增益，却线性增加耗时与内存 |
| PDF | 逐页栅格化（2x 倍率、长边 ≤ 2000px）后走同一管线 | 扫描 PDF 与图片同质处理 |

## 三、图像增强管线（`js/ocr-enhance.js`）

像素对象统一为 `{data: RGBA, width, height}`，全部为纯函数，可在 Node 中单测（不依赖 DOM / Canvas）。

### 1. 倾斜纠偏

1. 降采样到长边 700px 的灰度图，Otsu 求全局阈值取墨点（判定用 `<=`：Otsu 在双峰间隙并列最优时返回
   间隙下界，即暗簇上缘，用 `<` 会一个墨点都取不到）；
2. 对 -12°…+12° 按 2° 粗扫、再在最优角 ±2° 内按 0.5° 细化，每次按 `y' = y + (x − cx)·tan(a)` 做投影，
   取"行投影平方和最大"的角度；
3. 最优角绝对值 ≥ 0.6° 时执行剪切变换纠偏——逐列垂直平移，**不做旋转重采样**，因此不产生插值模糊；
4. 输出高度按最大位移加白边，宽度不变。

### 2. 低光照与对比度

直方图 2% / 98% 百分位拉伸到 0–255。动态范围已足够（`p98 − p2 < 12`）时跳过，避免对干净扫描件过处理。

### 3. 模糊增强

在降采样灰度上计算拉普拉斯方差；低于阈值（60）时对整幅做非锐化掩模（`g + 0.6·(g − blur3x3)`），
强化笔画边缘。三档增强动作（纠偏 / 低光照 / 锐化）会在识别完成后汇总到状态行。

### 4. 复杂背景压制（Sauvola 二值化）

局部自适应阈值：

```
T(x,y) = mean(x,y) · (1 + k · (std(x,y) / R − 1))     k = 0.25, R = 128
```

- 用积分图与平方积分图实现，复杂度 O(n)；
- 窗口取 `min(w,h) × 20%`，钳制 31–151px 并强制奇数。**窗口必须明显大于笔画宽度**——窗口相对笔画过小
  时笔画内部标准差趋零、阈值跌破墨值，会把笔画内部判成背景（镂空），直接毁掉识别；
- 背景渐变、阴影、桌面拍摄的偏色底都能被压平，文字保持为纯黑。

### 5. 去噪

二值图上 3×3 邻域墨点数 ≤ 2 的孤立点转白，去除椒盐噪点。

### 性能

| 图像 | 耗时（Node / 单线程，含全部五步） |
| --- | --- |
| 2600×2000（520 万像素） | 约 260ms |
| 1200×900 | 约 60ms |

相对一次 OCR 识别（数百毫秒到数秒）可忽略；主要内存开销是二值化的两张 Float64 积分图（约像素数 × 16 字节），
在 2600×2000 下约 83MB 峰值，随函数返回释放。增强失败不影响识别——自动回退原图并记录告警。

## 四、版面还原

### 表格

1. **聚行**：词级 bbox 按 y 中心排序，中心距 > 0.6 倍行高即新行；
2. **聚列**：按词左缘聚类（容差 = 词宽中位数 40%），列锚点排序后，每个词归入最近列；
3. **准入**：列支持率 ≥ max(2, 半数行)、列数 ≥ 2、行数 ≥ 2、填充率 ≥ 50%，否则判为非表格；
4. **对齐推断**：逐列比较 x0 离散度、x1 离散度与中心离散度，最小者且不超过容差即判定
   左 / 中 / 右对齐（三者相当则按左对齐）；
5. **列宽**：取列内格子的最大水平跨度，用于 DOCX 按比例分配列宽、Excel 换算字符宽。

### 段落

- 行距 > 0.75 倍行高即另起段落；
- 同段落内：两侧任一侧为 CJK 字符时直接连接（不插空格），纯西文之间以单空格连接；
- 首行缩进：段首 x0 相对页面左缘偏移 > max(1.2 × 行高, 12px) 时标记 `indent = 1`。

### 结构化模型

```js
doc = {
  blocks: [
    { type: 'p', text: '首行缩进的正文段落', indent: 1 },
    { type: 'table', rows: [['项目', '数量'], ['合计', '9']],
      aligns: ['left', 'right'], widths: [120, 60] }
  ],
  conf: 91.3,          // 行级置信度均值
  hasTable: true,
  page: { w: 1240, h: 1754 }   // 页面外接尺寸（词级 bbox 最大边界）
}
```

`page` 用于方向判定：宽高比 > 1.2 判为横向，决定 A4 版心初始方向与 DOCX 页面尺寸。

## 五、结果后处理

| 处理 | 规则 | 说明 |
| --- | --- | --- |
| 全半角归一 | 全角数字 / 字母 / 空格 → 半角 | OCR 常见输出形态 |
| 空格整理 | 压缩中文字符间冗余空格、去标点前空格、书名号内侧空格 | 提高可读性与后续解析准确率 |
| 数字上下文纠错 | `O/Q/D→0`、`I/l→1`、`Z→2`、`S→5`、`B→8`、`G→6` | **仅作用于含真实数字的字母数字串**；`ZOO`、`OK`、`plain` 等纯字母词不动 |
| 身份证号校验 | GB 11643-1999 加权 mod 11 校验 | 校验失败时逐位尝试混淆替换，**唯一解才纠错**，多解或纯数字错位一律不改 |
| 字段提取 | 手机号、日期、证件号 | 结果摘要显示在结果区下方（如「检测到：证件号 1（校验位纠错 1 个）、手机号 2」），不写入正文 |

## 六、导出格式对照

| 能力 | TXT | DOCX | XLSX |
| --- | --- | --- | --- |
| 段落 | 逐行纯文本 | `w:p` 段落，带 `w:ind firstLine="480"` 首行缩进 | 不适用 |
| 表格 | 按对齐补格的等宽文本网格 | 真 `w:tbl`：`tblGrid` 列宽按相对比例分配至版心 9026 twips、单元格 `w:jc` 保留对齐、六向单线边框 | 每张表格一个工作表，单元格定位到行列引用 |
| 页面方向 | 不适用 | 随版心：竖向 `11906×16838`，横向 `16838×11906 + orient="landscape"` | 不适用 |
| 数据类型 | 文本 | 文本 | 纯数字（≤11 位、非 0 开头）写数值 `<v>`，长编号 / 证件号保持文本避免 15 位精度截断 |
| 表头 | 无 | 无特殊样式 | 首行加粗 |
| 列宽 | 按展示宽度补齐 | 按识别相对宽度比例 | 相对像素宽 ÷ 7.5，钳制 8–60 字符宽 |

补充约定：

- **编辑优先**：文本框被用户修改后，DOCX 回退为纯文本段落导出（以人工修改为准），避免旧结构覆盖编辑结果；
  Excel 始终按识别到的原始表格结构导出，并在导出后提示。
- **多文件**：TXT / DOCX 以「===== 文件名 =====」分节；Excel 每张表格一个工作表，表名取文件标签
  （非法字符清洗、≤31 字符、重名追加序号）。
- **零依赖**：两种 OOXML 包都由项目内 `ZipUtil`（store 不压缩，带 CRC32 与 UTF-8 文件名标志）打包，
  不引入 docx / exceljs 等第三方库。

## 七、界面：A4 固定版心

- 结果区按 A4 比例固定：竖向 210:297、横向 297:210（CSS `aspect-ratio`，宽度驱动、高度随比例推导）；
  矮窗口分两档（≤880px / ≤740px）自动降宽，任何尺寸都不变形；
- 白纸黑字呈现（暗色主题下也是纸面观感），内容超长在版心内滚动；
- 方向切换即时生效；识别完成按 `page` 宽高比自动匹配原件方向（多页横向占多数则横向），可手动覆盖；
- 方向与 DOCX 导出联动，避免"版心横向、导出竖向"。

## 八、已知限制

- 手写体、艺术字、极低分辨率（短边 < 300px）识别效果有限；严重失焦与大面积遮挡无法通过增强复原；
- 表格依赖对齐的网格推定：无框线且列间留白极小的排版可能被判为段落；不还原单元格合并、框线样式与公式；
- 识别结果受语言包限制（简体中文 + 英文），其他语种需另行提供 traineddata；
- 二值化在彩色印章、彩色底纹面积较大时可能把印章并入文字笔画——此时可关闭「自动图像增强」重试。
