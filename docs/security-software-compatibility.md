# 安全软件兼容性指南（360 安全卫士 / 360 杀毒 误报防治）

> 适用版本：v1.3.0 起 · 2026-10-18
> 目标：降低尊泓工具箱在 360 安全卫士、360 杀毒、腾讯电脑管家、火绒等国产安全软件环境下被误报/拦截的概率，并提供申诉与验证流程。

---

## 一、误报原理速览

国产安全软件对**未签名**软件主要依赖三类引擎判断，本程序逐一对照：

| 引擎 | 判定依据 | 本程序现状 |
| --- | --- | --- |
| 特征库（病毒库） | 与已知病毒文件哈希/特征匹配 | 无恶意代码，命中概率低 |
| QVM 机器学习引擎 | 大量"特征"加权打分：无签名 + 冷门厂商 + 敏感行为组合 | **主要风险来源**（见第二节） |
| 行为防护（主动防御） | 运行期行为：写注册表、改文件关联、子进程注入、监听端口 | **次要风险来源**（见第二节） |

关键结论：**未签名 + 新发布的冷门安装包是最大变量**。同样的代码，签名后与积累了一定装机量的版本，误报率会显著下降。

## 二、风险点排查清单（代码审计结果）

### 已确认的低风险/已缓解项

| # | 行为 | 位置 | 现状 | 误报风险 |
| --- | --- | --- | --- | --- |
| 1 | spawn 7z.exe 压缩/解压 | electron/archive.js | 数组传参不经 shell、`windowsHide: true`、内置 LGPL 引擎 | 低。压缩工具类软件常见行为；但内置的 7z.exe 本身**未签名**，见 §四 |
| 2 | reg.exe 写 HKCU 注册表（压缩包图标关联） | electron/archive-icons.js | 仅用户级 Software\Classes、只接管无关联扩展名、System32 绝对路径、有备份可还原 | **中**。"改文件关联"是主动防御重点监控行为；用户级 + 不覆盖已有关联的设计已把风险降到合理范围，但首次使用可能弹窗 |
| 3 | ie4uinit -show 刷新图标缓存 | electron/archive-icons.js | 官方途径、5s 超时 | 低 |
| 4 | powershell CIM 查默认打印机 | electron/main.js | `-NoProfile`、System32 绝对路径、5s 超时、只读查询 | 低-中。powershell 子进程本身是监控重点，但只读且带完整参数 |
| 5 | rundll32 printui.dll 打印机属性对话框 | electron/main.js | System32 绝对路径、15s 超时 | 低 |
| 6 | 本地静态服务监听端口 | electron/static-server.js | 只绑 127.0.0.1 随机端口、非 0.0.0.0、有 Host 白名单 | 低。**不是网络后门特征**（不监听外网地址、不外连），文档口径已明确 |
| 7 | 隐藏窗口静默打印 | electron/main.js print:printImage | 沙箱窗口、合并单任务 | 低 |
| 8 | File System Access API 批量改名/写文件 | js/batch.js 等 | 用户逐次授权、原子 move | 低 |
| 9 | 无加壳/无混淆/无自修改代码 | 全局 | Electron + 明文 JS（asar），asar 可用 7z 直接解开 | **有利项**——壳/混淆是误报重灾区，本程序没有 |
| 10 | 无外联网络请求 | 全局 | CSP connect-src 'self'，无任何远程 API | **有利项** |

### 实测确认的风险点与本次处置

| # | 风险点 | 证据 | 处置 |
| --- | --- | --- | --- |
| A | **安装包与主程序无数字签名**（SmartScreen 警告 + QVM 打分高） | Get-AuthenticodeSignature 全部 NotSigned | 短期走白名单申诉（§五）；中期上代码签名（§四） |
| B | **内置 7z.exe 未签名** | 实测 `NotSigned`（7-Zip 官方分发的 exe 本身不带签名） | electron-builder 打包时已对本包内全部 exe 统一执行 signtool 签名流程，拿到证书后 7z.exe 会随之获得我方签名，无需额外处理 |
| C | **进程缺少 AppUserModelID**，任务栏身份模糊 | main.js 此前未设置 | **已修复**：`app.setAppUserModelId('com.zunhong.toolbox')` |
| D | **exe 版本资源信息不全**（公司/商标字段缺失） | electron-builder 默认输出 | **已修复**：build.win 增加 `legalTrademarks`，显式锁定 `requestedExecutionLevel: asInvoker`（明确向系统声明不要求管理员提权——提权类软件是重点盯防对象） |
| E | 便携版单文件 exe | 打包配置 | 保留（用户需要），但**发放口径建议优先 NSIS 安装版**——自解压单文件在 QVM 的打分天然偏高 |

### 设计上刻意避开的高危特征（继续保持）

- ❌ 不写 HKLM / 不注册服务 / 不加驱动 / 不写启动项 / 不设计划任务
- ❌ 不做内存注入、不 hook 其他进程、不键盘记录
- ❌ 不下载并执行远程代码（无自动更新外链，更新走用户手动安装）
- ❌ 不混淆、不加壳、不隐藏窗口骗取用户点击

## 三、已实施的改进（v1.3.0）

1. **electron/main.js**：Windows 下设置 `app.setAppUserModelId('com.zunhong.toolbox')`，进程与应用身份绑定。
2. **package.json**（build.win）：
   - `requestedExecutionLevel: "asInvoker"` —— exe 清单显式声明不提权；
   - `legalTrademarks: "尊泓工具箱"` —— 补全版本资源商标字段。
3. 以上改动不影响任何现有功能与测试（npm test / lint 全绿）。

## 四、代码签名建议（中期最有效的手段）

### 证书选型对比

| 方案 | 年费（参考） | SmartScreen 信誉 | 360 识别 | 适用 | 备注 |
| --- | --- | --- | --- | --- | --- |
| **OV 代码签名证书**（DigiCert/Sectigo/GlobalSign，国内经销：亚洲诚信/沃通/锐成） | ¥800–2,000 | 需装机量积累（数周） | 签名入库后基本不误报 | 预算有限起步 | 需企业/个体工商户资质，USB Key 或 HSM 存私钥 |
| **EV 代码签名证书** | ¥2,000–4,000 | **立即获得**信誉 | 同上 | 正式商用推荐 | 需企业实体（营业执照），硬件私钥，验证流程 1–2 周 |
| Azure Trusted Signing | ~$9.99/月 | 立即 | 同上 | ❌ 目前不对中国大陆主体开放 | 仅列作对照 |

**结论**：有公司实体（尊泓（湖北）健康有限公司）→ 直接上 **EV 证书**，一次到位；个体开发者过渡期可用 OV。

### 拿到证书后的打包配置（electron-builder 26）

```jsonc
// package.json → build.win（示例，非当前配置）
{
  "certificateSubjectName": "尊泓（湖北）健康有限公司",  // EV 证书主体名
  "rfc3161TimeStampServer": "http://timestamp.digicert.com",
  "signAndEditExecutable": true
}
```

- electron-builder 会自动签**主程序、卸载器、内置 7z.exe、elevate.exe** 及 NSIS 安装包（v1.3.0 构建日志已确认签名链路打通，仅缺证书）。
- **必须带 RFC3161 时间戳**：证书过期后已分发版本仍有效。
- 签名后旧版用户升级：新签名与旧无签名版本安装包不互通时，建议卸载重装一次过渡。

## 五、白名单申诉流程说明

### 360 安全卫士（主渠道）

1. 打开 **360 软件开放平台**：`https://open.soft.360.cn`，注册开发者账号（企业资质优先，审核权重更高）。
2. 提交「软件收录/误报申诉」：
   - 软件名称、版本、官网（可填 Gitee/GitHub 仓库页）；
   - **上传安装包文件本体**（Setup 1.3.0.exe 与便携版分别提交）；
   - 开发者信息 + 联系方式；如有签名证书一并填写。
3. 360 会采集样本入多引擎（含 QVM）人工复核，**一般 3–7 个工作日**；通过后该哈希加入白名单库，全量用户不再报毒。
4. **每次发版都要重新提交收录**——白名单按文件哈希生效，版本变了哈希就变（签名后按证书链信誉走，收录一次长期受益）。

### 360 杀毒（补充渠道）

- 误报提交页：`https://www.sd.360.cn`（或 360 杀毒 → 病毒查杀 → 误报申诉入口）；
- 也可发邮件至 360 误报申诉邮箱（官网「联系我们」页公示为准），附安装包 + 误报截图。

### 其他国产安全软件（同步做，覆盖主流装机）

| 软件 | 申诉入口 |
| --- | --- |
| 腾讯电脑管家 | `https://wp.qq.com`（URL 举报/软件申诉） |
| 火绒安全 | `https://bbs.huorong.cn` 误报反馈区，或 huorong.cn 客服渠道（响应快，开发者友好） |
| 金山毒霸 | `http://www.ijinshan.com` 误报申诉 |
| 微软 Defender | `https://www.microsoft.com/wdsi/filesubmission`（SmartScreen 申诉，签名后自动解除） |

### 申诉材料建议统一准备

1. 安装版 + 便携版两份产物（发版时各留一份存档，哈希固定）；
2. 软件功能说明（可直接引用本仓库 README「功能」一节）；
3. 「为什么会有这些行为」的一句话解释：写注册表=压缩包图标关联（用户级、可还原）、spawn 7z=内置解压引擎、监听端口=本机 127.0.0.1 离线渲染服务；
4. 公司/开发者资质材料。

## 六、兼容性验证测试步骤

### 第 1 步：基线扫描（本地，发版必做）

1. 在 [VirusTotal](https://www.virustotal.com) 上传 `Setup 1.3.0.exe` 与便携版，记录结果：
   - 关注 **360（QVM/AI 引擎）**、Microsoft、微步等国内相关引擎的标记；
   - 未签名新版本被 1–3 家冷门引擎标「低风险/可疑（Heur/Susp）」属正常，**有 2 家以上报毒名（Trojan/Backdoor 类）才需要警惕**。
2. 用 `signtool verify /pa` 或资源管理器→属性→数字签名检查（上证书后）。

### 第 2 步：干净环境基线（无安全软件）

1. 干净 Windows 10/11 虚拟机（或 Sandbox）安装运行：
   - 安装 → 首次启动 → 六个模块逐一进入；
   - 重点执行：压缩/解压（触发 7z spawn）、压缩包图标关联（触发 reg + ie4uinit）、直接打印（触发 rundll32/powershell）。
2. 确认零异常后作为行为基线。

### 第 3 步：360 实机测试（关键）

1. 虚拟机或测试机安装 **360 安全卫士（仅卫士）**，恢复默认拦截等级：
   - 重装本程序 → 观察安装过程是否被拦（NSIS per-user 安装一般不弹）；
   - 启动软件 → 观察 QVM 首次扫描是否弹「未知软件」提示；
   - 逐一执行第 2 步的重点操作，**记录每个弹窗截图**（申诉时要用）；
   - 检查 360「信任区」与「拦截记录」，确认它标记的具体文件与理由。
2. 单独安装 **360 杀毒**（可与卫士分开测）做全盘快速扫描，看是否被隔离。
3. 测试用户视角的解除路径：360 弹窗上的「信任并加入白名单」能否正常放行、放行后功能是否完整。

### 第 4 步：申诉与签名后复测

1. 按第五节提交申诉 → 等待入库 → **同哈希**复测第 3 步，确认零弹窗。
2. 拿到签名证书后重新打包 → 复测第 1、3 步，确认 SmartScreen 与 360 均不再提示。
3. 每次发版重复：VT 扫描 → 360 实机 → 新版本申诉提交（未上 EV 证书期间）。

### 回归门禁（每次改动后）

```bash
npm test          # 18 套件，退出码必须为 0
npm run lint      # 0 告警
npm run verify    # 含打包版 E2E（有产物时）
```

## 七、长期策略备忘

- **发版存档**：每个版本的两份 exe + 安装包哈希（SHA-256）留档，申诉时按哈希提交。
- **升级证书**：EV 证书到位后，在 CHANGELOG 与官网口径注明「已签名」，用户下载页展示证书主体名。
- **行为克制**：后续新功能继续遵守 §二「刻意避开的高危特征」清单；任何要写 HKLM/服务/驱动的需求先过一遍本指南评估。
- **用户沟通**：若收到用户反馈被拦截，引导其查看 360 拦截详情→「信任并放行」，同时把截图反馈回来供申诉补充。
