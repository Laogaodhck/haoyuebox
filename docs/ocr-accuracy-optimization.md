# OCR 识别精度与命中率优化方案

> 版本：v1.4.2 开发期 · 2026-10-21
> 适用代码：`js/ocr-enhance.js`（增强与版面）、`js/docs-ocr.js`（识别编排）、`tools/eval-ocr.cjs`（评测）
> 实测报告：[ocr-eval-report.md](ocr-eval-report.md)（由评测工具自动生成，可复现）

本文回答四个问题：哪些场景识别效果差、差在哪（根因）；怎么改（流程与参数）；改了多少（量化对比）；以后怎么持续度量（指标与样例）。

---

## 一、典型失败场景与根因分析

结论先行：本轮通过"先量化、再改"的方式定位到 **5 个真实缺陷**，其中 2 个属于"看代码看不出来"的实现级缺陷，3 个属于策略选择错误。

| # | 场景 | 现象 | 根因（本轮实测确认） |
| --- | --- | --- | --- |
| 1 | 模糊 / 低对比度 | 笔画弱化后成片丢字，长行只剩中段 | 同一行内字符置信度差异大时，整行被计入"已识别"，缺少按行/按通道的择优机制；且图像增强实际未生效（见缺陷 A） |
| 2 | 倾斜文本 | 行基线错位，行数被合并或拆散 | 依赖 Tesseract 内部纠偏，超过约 2° 后行切分不稳；我们自己的纠偏通道此前从未真正执行（缺陷 A） |
| 3 | 低分辨率 / 小字 | 大量字符直接漏识（命中率 64.7%） | 行高 < 12px 时 Tesseract 的 x-height 估计失效；缺少"放大后重识别"通道（此前有小图放大，但放大目标固定 1000px 且作用于已被破坏的增强图） |
| 4 | 复杂背景（渐变 + 噪点） | 背景被当成文字块，行内串入杂字 | 无条件的 Sauvola 二值化会把细噪点固化为墨点；实测二值化在该场景 CER 69.4%，原图直识仅 3.5% |
| 5 | 复杂表格 | 列错位、单元格串列、数字与文字混行 | ① 列聚类仅按 x0 距离，缺少"列必须有稳定对齐边"与"每行词数应接近列数"的判据，导致普通多行正文被误判为表格（缺陷 C）；② 单元格重识别会采纳"置信度更高但内容更错"的裁剪碎片（缺陷 D） |
| 6 | 文字定位偏差 | 稀疏分散文字只识到部分区域 | 基座分页模式 `SINGLE_BLOCK` 假定整页一个文本块，对分散标注不友好；缺少稀疏通道（PSM 11）触发条件 |
| 7 | 多语言混排 | 中英数混排时数字/符号被切成两层行 | 分词粒度受 `preserve_interword_spaces` 影响（缺陷 B）；另外 PSM 参数在 worker 上有状态，跨文件复用会互相污染（缺陷 E） |

### 本轮定位到的实现级缺陷

| 编号 | 缺陷 | 影响 | 证据 |
| --- | --- | --- | --- |
| A | `ctx.putImageData(r.px, …)` 传入普通对象而非 `ImageData`，抛 `TypeError` 后被上层 `catch` 静默回退原图 | **图像增强（纠偏/拉伸/锐化/二值化）自 v1.4.0 上线以来从未真正生效**，所有"增强"效果均为 0 | 浏览器内实测报 `parameter 1 is not of type 'ImageData'`；修复后低分辨率场景 CER 从 35.3% 降至 3.5% |
| B | 显式传 `preserve_interword_spaces: '1'` | 改变分词粒度，把列间空白并入词，破坏基于词级 bbox 的列聚类，实测导致表格列丢失（数量列整列消失） | 表格场景 CER 0% → 17.6% |
| C | 表格检测门槛过松（2 行即可、50% 填充率） | 4 行普通正文被判为表格，输出时"按列裁掉"其余文字，表现为长行截断 | 正文场景行召回 100% → 75%，CER 2.4% → 9.4% |
| D | 单元格重识别只要置信度 +3 就采纳 | 裁剪粒度不足时把 `摊` 识别为 `难`（置信更高、结果更错） | 表格 CER 5.9% → 8.8%，单元格准确率未提升 |
| E | Tesseract worker 的 `tessedit_pageseg_mode` 有状态，跨调用泄漏 | 单元格重识别设的 PSM 7、稀疏通道设的 PSM 11 会污染下一张图的基线通道，"同图不同结果" | 连续评测中后段场景集体劣化，显式重置后消失 |

> 这 5 项说明：**OCR 优化首先是"确认管线真的按预期执行"**。若不做量化评测，A 类缺陷会长期潜伏且被误认为"算法已达上限"。

## 二、改进后的识别流程

```
文件 → 解码/缩放 → 通道 1：原图 + 基座 PSM(6)  ── 质量评估（行高/置信度/亮度）
                                   │
        ┌──────────────────────────┴──────────────────────────┐
        │  仅在质量信号差时启用像素变体（各变体需评分超当前 5%）  │
        │   · 小字（行高<18px，或<24px 且长边<1200）→ 2x 放大   │
        │   · 低置信(<55) 或整体偏暗(<200) → 灰度增强（纠偏/    │
        │     百分位拉伸/模糊锐化）                            │
        │   · 暗底/反色底（均值<110）→ 二值化 + 极性归一        │
        └──────────────────────────┬──────────────────────────┘
                                   │
        通道 4：仍严重劣化（置信<60 或行数≤2）→ AUTO(3)/稀疏(11)
                                   │
      版面还原（表格检测/段落重建）→ 数字型低置信单元格重识别（预算 60 格）
                                   │
                        文本 / DOCX / XLSX 导出
```

设计要点：

1. **原图优先**：实测原图直识在 6/8 场景最优，无条件二值化反而损害清晰件与纹理背景，因此把增强从"默认执行"改为"按症状触发"。
2. **变体需过门槛**：每个变体的评分必须超过当前最佳 5%（`gain=1.05`）才采纳，避免"多跑一遍反而更差"。
3. **坐标一致性**：单元格重识别使用"实际参与识别的那张画布"（可能是放大/增强后的副本），避免 bbox 错位。
4. **参数卫生**：每次识别显式传 PSM，单元格重识别后重置参数，杜绝跨文件污染。

## 三、参数配置说明

| 参数 | 值 | 作用 | 调整依据 / 预期收益 |
| --- | --- | --- | --- |
| `MULTI.psmBase` | 6（SINGLE_BLOCK） | 基座分页模式 | 与 tesseract.js worker 默认值一致（即线上实际行为）；显式传入可防参数泄漏 |
| `MULTI.psmAuto` | 3（AUTO） | 版式复杂且基座漏行时的备选 | 多栏/图文混排比 SINGLE_BLOCK 更能分离区域 |
| `MULTI.psmSparse` | 11（SPARSE_TEXT） | 稀疏标注（海报、截图小字） | 行数 ≤2 时启用 |
| `MULTI.lowConf` | 60 | 触发版式回退的置信度下限 | 阈值从 78 降到 60：78 会在正常文档上误触发，白跑一遍（实测稀疏场景 1.38s → 0.32s） |
| `MULTI.pixelConf` | 55 | 无条件启用灰度变体的置信度下限 | 低于此值说明识别已严重劣化，值得多花一遍 |
| `MULTI.minLinePx` | 18（配 1200px 长边条件） | 小字判定 | 实测 22px 文字在大画布上无需放大；仅真小字/缩略图放大 |
| `MULTI.gain` | 1.05 | 变体采纳门槛 | 1.0 会抖动式换通道；1.08 会错过真实改善，1.05 为实测折中 |
| `MULTI.cellConf` | 70 | 单元格重识别阈值 | 高于 70 基本正确，重识别收益为负 |
| `MULTI.maxCells` | 60 | 单元格重识别预算 | 单页最坏约 +5s，防止超大表格拖垮交互 |
| 单元格重识别采纳 | conf +10 且 ≥75、字数比 0.8–1.25、**仅数字型单元格** | 防"置信更高但更错" | 中文短格实测出现 `摊→难`，因此限定数字格；数字格可用字符集校验 |
| Sauvola `k` | 0.25，窗口短边 20% 钳制 31–151px | 复杂背景二值化 | 窗口小于笔画宽度会产生笔画镂空（内部 std→0，阈值跌破墨值） |
| 缩放上限 | 长边 2600px（输入）、单页 2000px（PDF） | 控制内存与耗时 | 再大对准确率无显著增益 |
| 倾斜细化 | 粗扫 2° + 细化 0.25° | 纠偏精度 | 0.5° 步进在长行上仍有 1–2px 残差 |

## 四、评估指标定义

所有文本指标基于**归一化文本**：NFKC（全半角统一）+ 去除所有空白 + 拉丁字母小写。中文不受大小写影响；空白不计入（排版差异不应算作识别错误）。

| 指标 | 定义 | 计算方式 | 说明 |
| --- | --- | --- | --- |
| CER（字符错误率） | 与标准答案的字符级差异占比 | `CER = (S + D + I) / N` | N = 标准答案字符数；S 替换、D 漏识、I 多识，由 Levenshtein 对齐回溯得到 |
| 字符命中率（召回） | 正确识别的字符占标准答案比例 | `Recall = M / N` | **最直观的"命中率"** |
| 字符精确率 | 正确字符占输出比例 | `Precision = M / (M + S + I)` | 衡量"多识别出的垃圾字符" |
| F1 | 精确率与召回的调和均值 | `F1 = 2PR/(P+R)` | 单值汇总 |
| 行召回 | 整行被正确还原的比例 | 每行取最相似输出行，相似度 = `1 - dist/max(len)`，≥0.8 计命中 | 衡量排版级还原能力 |
| 行序准确率 | 第 i 行是否与第 i 条输出对应 | 同位置相似度 ≥0.8 计命中 | 衡量阅读顺序/定位是否错乱 |
| 单元格准确率 | 表格单元格文本完全一致的比例 | `匹配格数 / 总格数` | 表格场景专用 |
| 列数与对齐正确性 | 推断列数、列对齐是否与标准一致 | 布尔 | 表格结构指标 |
| 耗时 | 单页完整管线毫秒数 | `performance.now()` 包裹 | 含增强与多通道，反映真实成本 |

**统计口径**：逐场景计算后，总体指标取各场景算术平均（本方案 8 个场景权重相同），避免长文本场景淹没短文本场景的问题。

样例由 `tools/eval-ocr.cjs` 在浏览器内用 Canvas 现场渲染，**不含真人素材**，坐标、字体、噪声种子均固定，可重复运行。

## 六、实测对比（优化前 → 优化后）

「前」= v1.4.1 行为（单遍识别、基座 PSM 6、无有效增强）；「后」= 本方案（质量门控多通道 + 版面/单元格策略）。

| 场景 | CER | 字符命中率 | 行召回 | 单元格准确 | 耗时 |
| --- | --- | --- | --- | --- | --- |
| 清晰文档 | 2.4% → 2.4% | 97.6% → 97.6% | 100% → 100% | — | 942 → 549 ms |
| 模糊 + 低对比度 | 2.4% → 2.4% | 97.6% → 97.6% | 100% → 100% | — | 483 → 449 ms |
| 整体倾斜 3° | 4.7% → 4.7% | 95.3% → 95.3% | 25% → 25% | — | 376 → 434 ms |
| **低分辨率（小字）** | **35.3% → 3.5%** | **64.7% → 96.5%** | **0% → 100%** | — | 305 → 1096 ms |
| 复杂背景 | 3.5% → 3.5% | 97.6% → 97.6% | 100% → 100% | — | 550 → 526 ms |
| 复杂表格 | 5.9% → 5.9% | 94.1% → 94.1% | 100% → 100% | 83.3% → 83.3% | 166 → 177 ms |
| 稀疏分散 | 0.0% → 0.0% | 100% → 100% | 100% → 100% | — | 298 → 322 ms |
| 中英数混排 | 3.8% → 3.8% | 97.1% → 97.1% | 100% → 100% | — | 431 → 436 ms |
| **平均** | **7.2% → 3.3%** | **93.0% → 97.0%** | — | — | **444 → 499 ms（+12%）** |

**结论**

- **低分辨率是唯一可量化的精度提升点**：CER −31.8pt、命中率 +31.8pt、行召回 0%→100%，代价是单页多 0.8s（仅该场景触发放大通道）。
- **其余 7 个场景指标持平**，说明改动没有引入回归——这一点比"某项指标大涨"更关键，因为本轮修复的 5 个缺陷原本都会造成**劣化**（详见第一节表格）。
- 平均耗时 +12%，主要是低分辨率场景的放大通道；清晰文档反而因"不再盲目二值化"快了约 40%。
- 倾斜场景行召回 25% 属合成样例特性（3° 旋转后 Tesseract 把两行合并），CER 与命中率仍与优化前持平，未纳入本轮改动范围。

### 未采纳方案与原因（科学记录）

| 方案 | 实测结果 | 结论 |
| --- | --- | --- |
| 无条件 Sauvola 二值化 | 清晰件 CER 2.4%→9.4%、噪点背景 3.5%→69.4% | 弃用，改为暗底/反色专用通道 |
| 灰度 + 百分位拉伸（全量） | 噪点背景 CER 3.5%→230.6% | 仅在低置信/偏暗时启用 |
| 全量单元格重识别（含中文） | 表格 CER 5.9%→8.8%（`摊→难`） | 限定数字型单元格 |
| `preserve_interword_spaces=1` | 表格列丢失，CER 0%→17.6% | 移除 |
| 无条件 PSM 3（AUTO）作为基座 | 表格中列丢失、长行截断 | 弃用，PSM 3 仅作备选 |

## 七、后续可继续优化的方向

1. **行级融合**：同时保留两个通道的 blocks，按行 bbox 重叠择优合并，而非整页择优（当前整页评分会丢弃"部分更好"的通道）。
2. **模糊度驱动的锐化强度**：当前 `unsharp` 固定 0.6，可按拉普拉斯方差自适应。
3. **表格框线检测**：基于形态学检测横竖线，用于判定单元格合并（当前仅靠文本对齐推断）。
4. **倾斜场景**：行召回偏低，可尝试"纠偏后再跑一遍并整页择优"，代价约 +0.4s。
5. **真实素材集**：合成样例便于复现，但应在 `fixtures/`（不入库）补充真实扫描件/手机拍照样本，作为发布前的人工抽检集。
