# OCR 识别精度与命中率优化方案

> 版本：v1.7.0 开发期 · 2026-10-30；v1.7.1 真实素材抽检增补 · 2026-10-31；v1.7.2 真实素材六项修复 · 2026-11-13（更早：v1.4.2、v1.6.x）
> 适用代码：`js/ocr-enhance.js`（增强与版面）、`js/docs-ocr.js`（识别编排）、`tools/eval-ocr.cjs`（评测）
> 实测报告：[ocr-eval-report.md](ocr-eval-report.md)（由评测工具自动生成，可复现）、[ocr-real-report.md](ocr-real-report.md)（真实素材，13 张）

本文回答四个问题：哪些场景识别效果差、差在哪（根因）；怎么改（流程与参数）；改了多少（量化对比）；以后怎么持续度量（指标与样例）。

## 一、典型失败场景与根因分析

结论先行：v1.4.2 轮通过"先量化、再改"的方式定位到 **5 个真实缺陷**，其中 2 个属于"看代码看不出来"的实现级缺陷，3 个属于策略选择错误；v1.7.0 轮又定位到 4 个（见下文"本轮缺陷"）。

| # | 场景 | 现象 | 根因（本轮实测确认） |
| --- | --- | --- | --- |
| 1 | 模糊 / 低对比度 | 笔画弱化后成片丢字，长行只剩中段 | 同一行内字符置信度差异大时，整行被计入"已识别"，缺少按行/按通道的择优机制；且图像增强实际未生效（见缺陷 A） |
| 2 | 倾斜文本 | 行基线错位，行数被合并或拆散 | 依赖 Tesseract 内部纠偏，超过约 2° 后行切分不稳；我们自己的纠偏通道此前从未真正执行（缺陷 A） |
| 3 | 低分辨率 / 小字 | 大量字符直接漏识（命中率 64.7%） | 行高 < 12px 时 Tesseract 的 x-height 估计失效；缺少"放大后重识别"通道（此前有小图放大，但放大目标固定 1000px 且作用于已被破坏的增强图） |
| 4 | 复杂背景（渐变 + 噪点） | 背景被当成文字块，行内串入杂字 | 无条件的 Sauvola 二值化会把细噪点固化为墨点；实测二值化在该场景 CER 69.4%，原图直识仅 3.5% |
| 5 | 复杂表格 | 列错位、单元格串列、数字与文字混行 | ① 列聚类仅按 x0 距离，缺少"列必须有稳定对齐边"与"每行词数应接近列数"的判据，导致普通多行正文被误判为表格（缺陷 C）；② 单元格重识别会采纳"置信度更高但内容更错"的裁剪碎片（缺陷 D） |
| 6 | 文字定位偏差 | 稀疏分散文字只识到部分区域 | 基座分页模式 `SINGLE_BLOCK` 假定整页一个文本块，对分散标注不友好；缺少稀疏通道（PSM 11）触发条件 |
| 7 | 多语言混排 | 中英数混排时数字/符号被切成两层行 | 分词粒度受 `preserve_interword_spaces` 影响（缺陷 B）；另外 PSM 参数在 worker 上有状态，跨文件复用会互相污染（缺陷 E） |

### 本轮定位到的实现级缺陷

| 编号 | 缺陷 | 影响 | 证据 |
| --- | --- | --- | --- |
| A | `ctx.putImageData(r.px, …)` 传入普通对象而非 `ImageData`，抛 `TypeError` 后被上层 `catch` 静默回退原图 | **图像增强（纠偏/拉伸/锐化/二值化）自 v1.4.0 上线以来从未真正生效**，所有"增强"效果均为 0 | 浏览器内实测报 `parameter 1 is not of type 'ImageData'`；修复后低分辨率场景 CER 从 35.3% 降至 3.5% |
| B | 显式传 `preserve_interword_spaces: '1'` | 改变分词粒度，把列间空白并入词，破坏基于词级 bbox 的列聚类，实测导致表格列丢失（数量列整列消失） | 表格场景 CER 0% → 17.6% |
| C | 表格检测门槛过松（2 行即可、50% 填充率） | 4 行普通正文被判为表格，输出时"按列裁掉"其余文字，表现为长行截断 | 正文场景行召回 100% → 75%，CER 2.4% → 9.4% |
| D | 单元格重识别只要置信度 +3 就采纳 | 裁剪粒度不足时把 `摊` 识别为 `难`（置信更高、结果更错） | 表格 CER 5.9% → 8.8%，单元格准确率未提升 |
| E | Tesseract worker 的 `tessedit_pageseg_mode` 有状态，跨调用泄漏 | 单元格重识别设的 PSM 7、稀疏通道设的 PSM 11 会污染下一张图的基线通道，"同图不同结果" | 连续评测中后段场景集体劣化，显式重置后消失 |

> 这 5 项说明：**OCR 优化首先是"确认管线真的按预期执行"**。若不做量化评测，A 类缺陷会长期潜伏且被误认为"算法已达上限"。

### 本轮（v1.7.0）定位到的缺陷

| 编号 | 缺陷 | 影响 | 修复 |
| --- | --- | --- | --- |
| F | 倾斜页只有识别前的像素纠偏，没有"纠偏后重识别"通道；且整页评分只看字符，看不出行结构被破坏 | 3° 倾斜时 CER 4.7%、行召回 25%（两行被合并成一行），排版整体错乱 | 新增 `skewAngle` 统计 + 纯纠偏通道：\|倾角\| ≥ 1.2° 时补跑一遍，采纳条件是"评分不掉（≥98%）且行重叠更少"；倾斜场景 CER 1.2%、行召回 100% |
| G | 表格列聚类按"词心到列心距离"归列 | 同格内的多个词（`项 目`、`9 1,280.50`）被当成两列，或把邻格词吸进本列锚点，列数虚增、单元格串位 | 改为"先按行内间隙合并同格词，再按左右边缘/重叠度聚类列"；单元格准确率 83.3% → 100% |
| H | 文本归一缺少中文标点与日期间距规则 | `日期：` 常被识成 `日期:`；`2026 年 10 月` 保留中文排版不该有的空格 | 中文后 ASCII 标点转全角（西文上下文不变）；数字与 年月日 之间的空格去除 |
| I | 数字上下文纠错按"整串含数字就替换"处理 | 型号/编号被改坏：`A12-38B` → `A12-388`、`B1280` → `81280`；而原始识别其实是对的 | 改为令牌级：仅当令牌"含数字、且除易混字符外没有其他字母"（如 `138O0O12345`、`l02`）才改写；`A12-38B`、`X7-2B`、`K9/O2` 原样保留 |

> 缺陷 I 尤其说明"后处理也要有边界"：此前评测把 `A12-38B` 记在识别错误里，实际是纠错规则自己制造的。

## 二、改进后的识别流程

```
文件 → 解码/缩放 → 通道 1：原图 + 基座 PSM(6)  ── 质量评估（倾角/行高/置信度/亮度）
                                   │
        ┌──────────────────────────┴──────────────────────────┐
        │  仅在质量信号差时启用变体（像素变体需评分超当前 5%）  │
        │   · 倾角 ≥1.2° → 纯纠偏重识别（采纳看行重叠是否更少） │
        │   · 小字（行高<18px，或<24px 且长边<1200）→ 2x 放大   │
        │   · 低置信(<55) 或整体偏暗(<200) → 灰度增强（纠偏/    │
        │     百分位拉伸/模糊锐化）                            │
        │   · 暗底/反色底（均值<110）→ 二值化 + 极性归一        │
        └──────────────────────────┬──────────────────────────┘
                                   │
        通道 4：仍严重劣化（置信<60 或行数≤2）→ AUTO(3)/稀疏(11)
                                   │
      版面还原（表格列聚类/段落重建）→ 数字型低置信单元格重识别（预算 60 格）
                                   │
                    文本归一 → 文本 / DOCX / XLSX 导出
```

设计要点：

1. **原图优先**：实测原图直识在 6/8 场景最优，无条件二值化反而损害清晰件与纹理背景，因此把增强从"默认执行"改为"按症状触发"。
2. **变体需过门槛**：每个变体的评分必须超过当前最佳 5%（`gain=1.05`）才采纳，避免"多跑一遍反而更差"。
3. **版面看结构，不只看字符**：倾斜页的纠偏通道评分常常只差零点几个百分点（字符数甚至更多），但行 bbox 互相重叠、段落被合并；因此纠偏通道改用"评分不掉 + 行重叠率更低"的结构判据。
4. **后处理只做有把握的改写**：标点/空格归一限定上下文，数字纠错限定令牌形态，宁可不改也不把正确内容改错。
5. **坐标一致性**：单元格重识别使用"实际参与识别的那张画布"（可能是放大/增强后的副本），避免 bbox 错位。
6. **参数卫生**：每次识别显式传 PSM，单元格重识别后重置参数，杜绝跨文件污染。

## 三、参数配置说明

| 参数 | 值 | 作用 | 调整依据 / 预期收益 |
| --- | --- | --- | --- |
| `MULTI.psmBase` | 6（SINGLE_BLOCK） | 基座分页模式 | 与 tesseract.js worker 默认值一致（即线上实际行为）；显式传入可防参数泄漏 |
| `MULTI.psmAuto` | 3（AUTO） | 版式复杂且基座漏行时的备选 | 多栏/图文混排比 SINGLE_BLOCK 更能分离区域 |
| `MULTI.psmSparse` | 11（SPARSE_TEXT） | 稀疏标注（海报、截图小字） | 行数 ≤2 时启用 |
| `MULTI.lowConf` | 60 | 触发版式回退的置信度下限 | 阈值从 78 降到 60：78 会在正常文档上误触发，白跑一遍（实测稀疏场景 1.38s → 0.32s） |
| `MULTI.pixelConf` | 55 | 无条件启用灰度变体的置信度下限 | 低于此值说明识别已严重劣化，值得多花一遍 |
| `MULTI.minLinePx` | 18（配 1200px 长边条件） | 小字判定 | 实测 22px 文字在大画布上无需放大；仅真小字/缩略图放大 |
| `MULTI.gain` | 1.05 | 变体采纳门槛 | 1.0 会抖动式换通道；1.08 会错过真实改善，1.05 为实测折中 |
| `MULTI.skewDeg` | 1.2（度） | 触发纯纠偏通道的倾角下限 | 1° 以内 Tesseract 自身可处理；阈值太低会让正常页白跑一遍（+0.5s） |
| 纠偏通道采纳 | 评分 ≥ 当前 98% 且行重叠率更低 | 防止"字符更多但排版更乱" | 实测 3° 倾斜页评分反而低 0.03%，但行重叠率 1.0 → 0、行召回 25% → 100% |
| 表格同格判定 | 行内词间隙 ≤ max(12px, 0.9×行高) | 合并 `项 目`、`9 1,280.50` 等同格碎片 | 小于该间隙的词多属同一格；再按左右边缘/50% 重叠聚列，容差 0.3×中位格宽 |
| 中文标点归一 | 仅 CJK 字符后的 `:;,!?` 转全角 | 修复 `日期:`、`合计:` 一类半角混排 | `Email: …` 等西文上下文保持半角；数字与「年月日」之间的空格去除 |
| 数字纠错边界 | 令牌含数字且除 `OoQIl\|ZSBGqD` 外无其他字母才改写 | 防止型号被改坏 | `A12-38B`、`X7-2B`、`K9/O2` 原样保留；`138O0O12345`、`l02` 正常纠错 |
| `MULTI.cellConf` | 70 | 单元格重识别阈值 | 高于 70 基本正确，重识别收益为负 |
| `MULTI.maxCells` | 60 | 单元格重识别预算 | 单页最坏约 +5s，防止超大表格拖垮交互 |
| 单元格重识别采纳 | conf +10 且 ≥75、字数比 0.8–1.25、**仅数字型单元格** | 防"置信更高但更错" | 中文短格实测出现 `摊→难`，因此限定数字格；数字格可用字符集校验 |
| Sauvola `k` | 0.25，窗口短边 20% 钳制 31–151px | 复杂背景二值化 | 窗口小于笔画宽度会产生笔画镂空（内部 std→0，阈值跌破墨值） |
| 缩放上限 | 长边 2600px（输入）、单页 2000px（PDF） | 控制内存与耗时 | 再大对准确率无显著增益 |
| 倾斜细化 | 粗扫 2° + 细化 0.25° | 纠偏精度 | 0.5° 步进在长行上仍有 1–2px 残差 |

## 四、评估指标定义

所有文本指标基于**归一化文本**：NFKC（全半角统一）+ 去除所有空白 + 拉丁字母小写。中文不受大小写影响；空白不计入（排版差异不应算作识别错误）。

| 指标 | 定义 | 计算方式 | 说明 |
| --- | --- | --- | --- |
| CER（字符错误率） | 与标准答案的字符级差异占比 | `CER = (S + D + I) / N` | N = 标准答案字符数；S 替换、D 漏识、I 多识，由 Levenshtein 对齐回溯得到 |
| 字符命中率（召回） | 正确识别的字符占标准答案比例 | `Recall = M / N` | **最直观的"命中率"** |
| 字符精确率 | 正确字符占输出比例 | `Precision = M / (M + S + I)` | 衡量"多识别出的垃圾字符" |
| F1 | 精确率与召回的调和均值 | `F1 = 2PR/(P+R)` | 单值汇总 |
| 行召回 | 整行被正确还原的比例 | 每行取最相似输出行，相似度 = `1 - dist/max(len)`，≥0.8 计命中 | 衡量排版级还原能力 |
| 行序准确率 | 第 i 行是否与第 i 条输出对应 | 同位置相似度 ≥0.8 计命中 | 衡量阅读顺序/定位是否错乱 |
| 单元格准确率 | 表格单元格文本完全一致的比例 | `匹配格数 / 总格数` | 表格场景专用 |
| 列数与对齐正确性 | 推断列数、列对齐是否与标准一致 | 布尔 | 表格结构指标 |
| 耗时 | 单页完整管线毫秒数 | `performance.now()` 包裹 | 含增强与多通道，反映真实成本 |

**统计口径**：逐场景计算后，总体指标取各场景算术平均（本方案 8 个场景权重相同），避免长文本场景淹没短文本场景的问题。

样例由 `tools/eval-ocr.cjs` 在浏览器内用 Canvas 现场渲染，**不含真人素材**，坐标、字体、噪声种子均固定，可重复运行。

| ID | 场景 | 构造方式 | 标准答案 |

## 六、实测对比（优化前 → 优化后）

口径说明：两列共用同一套后处理（表格列聚类、数字纠错、标点归一），因此「前」与「后」的差异只反映**识别通道策略**；对比早期版本时，后处理的改善会同时体现在两列上。

| 场景 | CER（前 → 后） | 字符命中率（前 → 后） | 行召回（前 → 后） | 单元格准确 | 耗时 |
| --- | --- | --- | --- | --- | --- |
| 清晰文档 | 1.2% → 1.2% | 98.8% → 98.8% | 100% → 100% | — | 905 → 500 ms |
| 模糊 + 低对比度 | 2.4% → 2.4% | 97.6% → 97.6% | 100% → 100% | — | 431 → 451 ms |
| 整体倾斜 3° | 3.5% → **1.2%** | 96.5% → **98.8%** | **25% → 100%** | — | 362 → 916 ms |
| **低分辨率（小字）** | **8.2% → 2.4%** | **92.9% → 97.6%** | **75% → 100%** | — | 293 → 1037 ms |
| 复杂背景 | 1.2% → 1.2% | 98.8% → 98.8% | 100% → 100% | — | 468 → 526 ms |
| 复杂表格 | 0.0% → 0.0% | 100% → 100% | 100% → 100% | **100%（前 100%）** | 157 → 172 ms |
| 稀疏分散 | 1.9% → 1.9% | 98.1% → 98.1% | 100% → 100% | — | 285 → 309 ms |
| 中英数混排 | 2.9% → 2.9% | 98.1% → 98.1% | 100% → 100% | — | 420 → 437 ms |
| **平均** | **2.7% → 1.6%** | **97.6% → 98.5%** | — | — | **415 → 544 ms（+31%）** |

本轮（v1.7.0）相对 v1.6.1 管线（同一评测脚本）的变化：

| 指标 | v1.6.1 | v1.7.0 | 说明 |
| --- | --- | --- | --- |
| 平均 CER（单遍 / 多通道） | 6.7% / 3.3% | **2.7% / 1.6%** | 表格列聚类与数字纠错对两列同时生效 |
| 字符命中率 | 93.5% / 96.8% | **97.6% / 98.5%** | 同上 |
| 倾斜 3° 行召回 | 25% | **100%** | 新增纠偏通道，CER 4.7% → 1.2% |
| 表格单元格准确率 | 83.3% | **100%** | 同格多词合并 + 按边缘聚列 |
| 单页耗时 | 约 430 ms | 约 544 ms | 仅倾斜/小字页触发额外通道；清晰页反而更快（905 → 500 ms） |

**结论**

- **倾斜页从"能读字但排版全乱"变为可用的结构化输出**：行召回 25% → 100%，代价约 +0.55s，且只在倾角 ≥1.2° 时发生。
- **表格结构修复是纯收益**：单元格 83.3% → 100%、表格场景 CER 0%，不增加任何识别次数。
- **小字与混排的剩余错误主要来自字形混淆**（放大到 1.5x/2x 也只能择一），继续加通道的边际收益已很低。
- 平均耗时上升来自纠偏/放大通道；无倾角、字号正常的页面耗时下降约 45%。

### 未采纳方案与原因（科学记录）

| 方案 | 实测结果 | 结论 |
| --- | --- | --- |
| 无条件 Sauvola 二值化 | 清晰件 CER 2.4%→9.4%、噪点背景 3.5%→69.4% | 弃用，改为暗底/反色专用通道 |
| 灰度 + 百分位拉伸（全量） | 噪点背景 CER 3.5%→230.6% | 仅在低置信/偏暗时启用 |
| 全量单元格重识别（含中文） | 表格 CER 5.9%→8.8%（`摊→难`） | 限定数字型单元格 |
| `preserve_interword_spaces=1` | 表格列丢失，CER 0%→17.6% | 移除 |
| 无条件 PSM 3（AUTO）作为基座 | 表格中列丢失、长行截断 | 弃用，PSM 3 仅作备选 |
| 空白文档也跑 1.5x/2x 放大通道 | 清晰场景 `合计` 修好但 `Email:` 冒号丢失，净收益为负 | 不新增放大通道，保留"小字才放大"的门控 |
| 纠偏通道用整页评分采纳 | 3° 倾斜页评分低 0.03%，正确结果被丢弃 | 改用结构判据（行重叠率） |

## 七、后续可继续优化的方向

1. **行级融合**：同时保留两个通道的 blocks，按行 bbox 重叠择优合并，而非整页择优（当前整页评分会丢弃"部分更好"的通道）。
2. **模糊度驱动的锐化强度**：当前 `unsharp` 固定 0.6，可按拉普拉斯方差自适应。
3. **表格框线检测**：基于形态学检测横竖线，用于判定单元格合并（当前仅靠文本对齐推断）。
4. **倾斜页的二次纠偏**：当前纠偏通道只做一次剪切变换；大角度（>8°）或镜头畸变下可迭代估角，并配合行级融合。
5. **真实素材集**：已建立 `testdata/ocr-real/`（不入库）与 `tools/eval-ocr-real.cjs`，本轮抽检结论见第八节。

## 八、真实素材抽检（2026-10-31）

合成场景已接近上限（平均 CER 1.6%），按计划先建立真实素材抽检集，**本轮不调参数**。样本 13 张（10 张主场景 + 3 张场景边界），GT 与扩展方式见 [ocr-real-samples.md](ocr-real-samples.md)，逐张指标见 [ocr-real-report.md](ocr-real-report.md)。

**基线**：主场景 10 张平均 CER **34.0%**、字符命中 74.0%、行召回 **20.0%**、关键字段命中 48.0%、表格单元格 78.6%；同一管线的合成场景 CER 为 1.6%。差距主要不在"单字认不出"，而在结构、彩色文字和表格通道。

### 定位到的问题

| 优先级 | 问题 | 证据 | 根因 |
| --- | --- | --- | --- |
| P0 | 紧密行距被整体并段 | 10 张主场景中 8 张行召回 0–9.1%（care-label / boarding-pass / train-ticket / lab-report / bank-receipt / baby-tag / haircare 全为 0）；仅 lab-table 92.9%、math 90.9% | `rebuildBlocks` 以行距 > 0.75·中位行高才分段；票据、标签、表单行距更紧，整页并成一段 |
| P1 | 缺少彩色通道 | 红色票号 `Z57A001950`→`SSTEOT`、`G7512`→`GZ>1<`；登机牌红章压坏 `12F`/`G11`/`15:55`；绿色标题 `纯臻营养护发素`→`MEHEEFIPRE` | 仅做灰度/二值化；红字、绿字在亮度通道对比度低，红章同时污染黑字 |
| P1 | 表格检测与门控 | equity-table 未检出表格，CER 72.9%、字段 1/8；同管线 lab-table 单元格 78.6% | 基座只跑 PSM 6 + 原图；质量信号判为"足够清晰"未触发放大/灰度；框线表格需专用通道 |
| P2 | 小字与小数点 | 检验单 `1.31`→`131`、`0.1`→`01`、`0.17`→`017`；baby-tag 字段 3/9；车票 `12B`→`128` | 2x 放大 + PSM 6 仍不足；标签/票据需按词高而非整页行高触发通道，并补 PSM 11/4 备选 |
| P2 | 数学与单位符号 | math CER 12.9%，`×`→`X`；`℃`→`"C` / ` C` | 后处理未覆盖乘号与温度单位；需上下文限定，避免改坏型号/编号 |
| P3 | 场景与竖排边界 | gate-sign 竖排 CER 630.4%（基本不可用）；street-sign 植被背景触发 full 二值化，CER 1175%、耗时 23.4s | 管线按横向文档设计；竖排需旋转通道，场景照应限制激进增强 |

### 建议的调参顺序（下一轮已全部实施）

1. **P0 结构保留**：按行距分布与行长方差区分"正文段落 / 表单标签 / 票据字段"，后者保留原始分行，并提供"保留分行"输出选项。收益最大且不改字符识别，DOCX/Excel 直接受益。
2. **P1 彩色通道**：在现有通道框架内增加 R/G/B 单通道变体，按文字/背景对比度择一；黑字+红章优先红通道，红字优先绿/蓝通道，沿用现有评分门槛防抖动。
3. **P1 表格通道**：以框线、列对齐作为表格信号，命中后走 2x 放大 + PSM 6/4 + 列聚类；验收口径为 equity-table 的表格检出率与单元格准确率。
4. **P2 小字与符号**：用词级高度替代整页行高触发放大；标签/票据补 PSM 11/4 备选；乘号、温度单位只做上下文归一。
5. **P3 场景边界**：先明确产品是否承诺"任意照片"；若不承诺，场景照只保证不崩、限时，不为竖排/植被背景投入通道。

> 主场景仅 10 张，指标用于定方向而非统计结论；新增真实样本后应重跑本报告再比较。

### 实施结果（2026-10-31 复测）

六项全部落地，同一 13 张样本复测（指标口径不变，报告见 [ocr-real-report.md](ocr-real-report.md)）：

| 指标 | 抽检基线 | 本轮后 | 变化 |
| --- | --- | --- | --- |
| 主场景 CER（10 张） | 34.0% | **24.2%** | −9.8pt |
| 主场景行召回 | 20.0% | **60.5%** | +40.5pt |
| 主场景字段命中 | 48.0% | **63.9%** | +15.9pt |
| 场景边界 CER（3 张） | 610.1% | **50.9%** | −559.2pt |
| 总体 CER（13 张） | 159.4% | **30.4%** | −129.0pt |
| 单页耗时（总体，场景兜底前 → 后） | 11050ms | **8514ms** | −23% |

逐项结果：

- **P0 行结构**：`layoutKind` 按行宽铺满率区分正文 / 表单，表单与票据逐行输出（`type:'line'`），正文页仍按行距并段。行召回由 20.0% 升至 60.5%，其余票据类样本的行召回不再整页为 0。
- **P1 彩色通道**：新增 R/G/中性三通道变体，按彩色像素占比与基座置信度门控，并叠加彩色行 / 彩色区域定向重识别（上限 8 行 / 6 区）。红色票号与红章遮挡区域恢复为可读文本，未采纳变体需文本重合度 ≥0.75 或评分领先 25%。
- **P1 表格**：画布框线检测优先于词级列聚类，表格检出后按列宽 / 对齐还原；equity-table 从「未检出表格、CER 72.9%、字段 1/8」变为「7 列、单元格 45.5%、CER 17.7%、字段 5/8」；lab-table 单元格 78.6% → 87.1%。表格均值 66.3% 低于基线的 78.6%，是因为基线只统计到 1 张表，本轮多检出 equity-table，属口径变化而非回退。
- **P2 小字与小数点**：糊片 + 中小字号启用 2x 双三次放大（清晰度门控），小数点按「去点文本一致且输出点数更多」接受行级候选。care-label CER 22.3% → 20.4%、lab-report-photo 23.1% → 15.7%、math-worksheet 12.9% → 6.4%；`1.31` → `131`、`0.1` → `01` 这类丢点由 Tesseract 裁剪重识别也无法复现圆点，保留保守接受规则，不强行改数字。
- **P2 符号归一**：仅上下文归一——整行含 `=` 时 `X/x` 还原为 `×`，数字后的 `C/°C/"C` 归一为 `℃`，型号 / 编号中的 `X` 不动；单测覆盖 `BX500`、`A12X38` 不被改写。
- **P3 场景与竖排**：整页评分极低（<12 且行均置信度 <30）时不再跑全尺寸变体，改为「缩到长边 700 → 二值化定位高置信中文词簇 → 原图裁切 2x 重识别」；定位失败则只过滤低置信乱码行。street-sign CER 1175% → 27.8%、耗时 23.4s → 14.9s；gate-sign 630.4% → 100.0%、15.4s → 3.4s。场景输出强制逐行并清理行首尾边框 / 箭头等符号（street-sign 行召回 0 → 25%）。

**竖排限制**：Tesseract chi_sim 不支持竖排中文。PSM 5（垂直版面）、逐字 PSM 10、逐字切分后拼接横条三种方案在 gate-sign 上均无法产出可用文本，因此竖排牌匾只保证「不输出满屏乱码、耗时受限」，不作为可识别场景；如后续有真实需求，应换用支持竖排的模型或专用 OCR 服务。

回归：`npm test` 全绿（OCR 两套断言 126 + 88），`npm run lint` 无告警；合成场景评测平均 CER 保持 1.6%（431ms → 681ms），无回退。
